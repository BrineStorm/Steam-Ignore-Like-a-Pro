# Directory Structure & Script Load Order

## Directory Structure

```
Steam-Ignore-Like-a-Pro/
├── platform/
│   ├── chromium/manifest.json   # MV3 manifest for Chrome/Edge
│   └── firefox/manifest.json    # MV3 manifest for Firefox
├── src/
│   ├── escape.js                # window.ILAP.Sanitizer (+ window.ILAP.newOwnerId, the lease/slot owner id, window.ILAP.serialChain, the per-context write chain the stats, queue, gate, ignore-log and DQ-registry read-modify-writes share, and window.ILAP.realInput, the real-input guard the DQ panel, the EQ toast and the automation notice wire their controls through): the pure helpers — escapeHTML (single HTML-escaper) + sanitizeName (storage-boundary name normalizer: strips <>, control chars → space, collapses whitespace, clamps to 120). ONE definition for ALL THREE worlds: loaded FIRST in content_scripts, first in popup.html and first in the SW's importScripts (neither of which loads utils.js), so the SW/log/curator copies that used to drift are gone
│   ├── settings-schema.js       # window.ILAP.Settings: the user settings' storage KEYS, DEFAULTS (the three gesture bindings, the Queue Helper mode), Q_MODES, GESTURES (the three right-button gesture values: what the MI detector checks before cancelling a menu that opens at press), BINDINGS (the six gesture-select values in menu order), OFF, UNIGNORE_KEYS, isOn (absent = on), normalizeShortcut (the legacy ignore-binding values) and normalizeUnignore (null for a value no build wrote). Pure; loaded right after escape.js in content_scripts and popup.html, and in the SW's importScripts — no module spells a settings key or default of its own, and none hand-rolls `!== false` either: a stored switch becomes a real boolean at the reader that fetches it (`ConfigReader._updateInternal`, `master-switch.js`, the popup's `_applyValues`)
│   ├── stats.js                 # window.ILAP.StatsLogic: the Last-Ignored record's shape — the three key names (ilap_ignored_count / _history / _last_ignored_name), the 20-entry history cap, and increment/decrement/pushHistory/nextState, plus countState and uncountState: the count-only halves, ±1, for an ignore that must be COUNTED but not SHOWN (a drained curator ignore — no name to display, and a job-sized batch would flush the history) and for a confirmed rollback, which takes its ignore back out of the total and equally leaves the history alone (a rolled-back entry still happened; what is UNDOABLE is ignore-log.js's question, not this one). The decrement is floored at 0: a rollback of a game ignored before install has no increment of its own to take back. ONE definition for the TWO worlds that WRITE it: utils.js StatsManager (content script) and background.js's shims (the SW recording a drained MI job via saveStats, a drained curator one via bumpCount, a drained undo via dropCount). Both worlds run all three writers on ONE serialized chain — they read-modify-write the same counter, so a second chain would lose a step where they overlap. Pure; only the chrome.storage read-modify-write around it stays per-world. popup.html loads it too, for the key names and the SOURCE labels only (it writes nothing). Also TOTAL_KEY (ilap_ignored_total, Steam's own ignore-list size as last read, with the counter as it stood then), totalState (that snapshot's write, on the same per-world chain as the counter writers: recordTotal in each world) and displayTotal (the popup's hover tip on the count: Steam's size plus what the counter moved since the read, null before any read — the counter is never a stand-in for it). Also SOURCE, every Last-Ignored history label (EQ and DQ, which their composition roots pass — the automators themselves save (name, appid) — and Manual Ignore's two), and miSourceLabel, the MI reason → label map both drain hosts use
│   ├── steam-net.js             # window.ILAP.SteamNet: the ignore POST's URL, form fields (ignoreFields / unignoreFields, less the sessionid) and result shape (ignoreResult: 429 + Retry-After; ignoreFailed), shared by the two per-world POSTs, and the shared Steam network READS — fetchWithTimeout (the 10 s deadline every Steam fetch goes through; optional per-call override, timer deliberately not cleared so the body read is covered too), fetchIgnoredAppsStrict (dynamicstore userdata → Map appid → ignore reason, null on any failure; USERDATA_LAG_MS, the ~15 s it lags a POST, which the drainer and ignored-total.js both wait out), probeLogin (/account/ redirect check) and probeLoginCached (the same probe behind ONE shared verdict cache — a confirmed session reused 60 s, a confirmed logout 10 s, a FAILED probe never cached, concurrent callers sharing the in-flight request; the two ignore-side gates ask through it, everything that needs a fresh answer keeps calling probeLogin), checkAppUnavailable (the appdetails success:false probe), fetchAppName (the sanitized localized name from appdetails, the last resort of game-name.js) and classifyRefusal (the verdict wrapper both drain hosts apply to a refused POST — marks a 400 as a permanent per-appid region lock so the drainer skips it in one attempt instead of burning MAX_FAILS, and, in the SW, before the halt counter sees it). ONE definition for the TWO worlds that talk to Steam: loaded after escape.js in content_scripts and second in the SW's importScripts; popup.html never fetches Steam, so the storage-plumbing duplication rule (store.js) does not apply here. The ignore/unignore POST is NOT here — it stays per-world on purpose (see the file's own header)
│   ├── toast.js                 # window.ILAP.showToast(html, duration): the shared bottom-right push card (.ilap-toast + its own <style>), used by the curator button and Manual Ignore's queue-full warning and one-time menu-at-press hint. EQ/DQ keep their own toasts — those are interactive surfaces, not one-shot cards
│   ├── utils.js                 # Content-script infrastructure (loaded after escape.js + steam-net.js; re-exports the SteamNet reads as window.ILAP.fetchWithTimeout / .fetchIgnoredAppsStrict / .classifyRefusal / SteamAuth.probeLogin): the cookie session id, the ignore/unignore POST (one local post(fields) for both), the lenient fetchIgnoredApps policy wrapper, the DOM login header (SteamAuth: resolveLogin for the UI locks, and hasLiveSession — the ONE ignore-side gate the rate governor and the Manual-Ignore gestures both ask, header trusted only when signed-IN, else the cached probe, tri-state so 'signed out' stays tellable from 'couldn't ask') and StatsManager
│   ├── ignored-total.js         # Keeps ilap_ignored_total fresh while nothing drains (a drain pass records it for free from its own userdata read): on a store page load with the master switch on, when the snapshot and the last attempt (ilap_ignored_total_poll, any tab) are both older than 15 min, claims the attempt, then reads userdata only on a live session (SteamAuth.hasLiveSession) — a signed-out read is an empty list and must never become 0, so an EMPTY read is kept only after a fresh probeLogin (the header can show signed-in on a session that has died since). Within 15 s of the last gate slot (IgnoreGate.lastSlotAt — userdata lags a fresh POST) it reads nothing and claims nothing. Not per account: a switch shows the old number for up to one TTL. Both platforms, after gate.js
│   ├── game-name.js             # window.ILAP.getGameName (sync) / resolveGameName (async): a game's display name from the DOM around one of its links — five strategies behind NameExtractionStrategyProvider.find (null when all miss), the "AppID <id>" placeholder applied at the facade, and SteamNet.fetchAppName as the async last resort. After utils.js and steam-net.js
│   ├── sw-handoff.js            # The page's half of the SW drain: caches the cookie sessionid into ilap_sw_sid (the worker cannot read document.cookie) and clears ilap_sw_halt, writing only on change so a same-value write never wakes the worker. Runs on every store page, after utils.js and curator/store.js (whose SW_SID_KEY / SW_HALT_KEY it writes). CHROMIUM ONLY — the Firefox manifest leaves it out on purpose: that platform drains from the content script, so nothing there would read the cached sessionid and nothing would clear it either (the reaper lives in the worker)
│   ├── master-switch.js         # window.ILAP.MasterSwitch.watch({ onInit, onChange }): the global `ilap_master_enabled` read once, then followed live (absent = ON; the change listener attaches only after the first read lands). For content-script modules that need that key alone — Discovery Queue controller, curator button; EQ, Manual Ignore and the widget read it inside their wider settings snapshots
│   ├── gate.js                  # window.ILAP.IgnoreGate: aggregate ignore-POST rate governor (reserve() a slot before every ignore across drainer/EQ/DQ; ilap_ignore_gate fixed min-gap; master + dead-session stop, the latter via SteamAuth.hasLiveSession — NOT from the sessionid cookie, which anonymous visitors also have; stopVerdict is asked OUTSIDE the claim chain because it can cost a network round trip, and it reports 'offline' apart from 'no-session' because "could not ask" and "signed out" do not recover alike — only 'disabled' is a state the extension itself owns, which is the one the SW parks its retry alarm on) — closes audit #1/#2. While the user is active on a Steam page (ilap_user_active_at, last 30 s) a background reservation without { gesture: true } waits ACTIVE_GAP (3 s) instead; noteNativeIgnore(status) folds an ignore POST that Steam's own page sent into the same stream (slot moved up to now, a 429 escalates the penalty)
│   ├── steam-activity.js        # The user's own activity on a Steam store page, told to IgnoreGate while the master switch is on (MasterSwitch.watch; off, it writes nothing): page load + trusted pointerdown/keydown outside the extension's own UI → noteUserActivity (throttled, 5 s); a PerformanceObserver on the page's resource timeline sees every ignore POST the PAGE sends (XHR or fetch, with or without the trailing slash, status via responseStatus — no extra permission, isolated world, verified live on Chromium and Firefox) → noteNativeIgnore; skips our own POSTs, which land in that timeline on Firefox, via ILAP.OwnIgnorePosts (utils.js). Content script only
│   ├── ignore-log.js            # window.ILAP.IgnoreLog: timestamped append log of every EXTENSION ignore {appid,name?,ts,source,curatorId?,undoneAt?} (cap 5000 FIFO; an MI change of reason is not logged — Undo only takes games off the list), chunked across ilap_ignore_log_index + ilap_ignore_log_c<seq> so a drain's append writes one small key; the undo feature's data source (Steam's rgIgnoredApps has no dates). Pure selectors (snapshotLastN/Since, undoableCount, reIgnoredAfter, lastUndoneForCurator) and chunk plans (appendPlan, chunkedPlan) + serialized getLog/append/markUndone, with a lazy migration of the legacy single-array key; self-contained, loaded in content_scripts AND popup.html
│   ├── undo-service.js          # window.ILAP.UndoService: injectable staging for undo jobs — a STATIC appid snapshot from the log (count or time scope) pushed into the shared curator queue as {type:'undo', curatorId:'undo'} (one at a time, same 3-job cap); the drainer branches on the type to POST remove=1
│   ├── surface.js               # window.ILAP.Surface: ilap_surface_mode helper (widget|popup mode, Steam-client UA detect, Ctrl+Alt+Shift+I escape-hotkey + per-platform label + shift-click mouse twin) — pure, loaded in content scripts AND popup.html
│   ├── background.js            # Chromium MV3 service-worker ENTRY (Phase 3; NOT in the --test build, which swaps in the empty background-test.js). Shims window→self, importScripts's escape.js + settings-schema.js + stats.js + steam-net.js + migrate.js + gate.js + ignore-log.js + curator/lease.js + curator/store.js + curator/drainer.js, then hosts a CuratorQueueDrainer that drains the queue with NO Steam tab open — it joins the existing lease/handoff protocol as just another drainer. SW-specific parts: sessionid from the ilap_sw_sid cache (mirrored into memory for the gate's sync read), its own ignore POST (the one Steam call that stays per-world — the reads come from steam-net.js) and its own storage RMW for stats (the record's shape comes from stats.js), a gate wrapper that refuses waits >20 s (the SW would die mid-sleep; a chrome.alarms alarm resumes at the penalty's end instead) and the ilap_sw_halt circuit breaker (2 consecutive failed POSTs — stale sid / missing Steam_Language — halt BEFORE the drainer's MAX_FAILS skip burns an appid; any store-page visit re-arms). One retry alarm ('ilap_sw_drain', ≥60 s) re-armed while drainable work remains, cleared when the queue empties, when the route is halted, or on a master-off stop — the only stop whose cure is a storage write this worker hears. Firefox: NOT used (unverified fetch behavior from an event page) — its background stays migrate.js only, the content-script drainer remains the FF path
│   ├── migrate.js               # Profile migrations (on Chromium loaded into the SW via background.js importScripts; on Firefox the sole event-page script; NOT in the --test build). One top-level act: where chrome.alarms is ABSENT there is no SW drain, so the worker's sessionid cache is reaped (ilap_sw_sid + ilap_sw_halt) — Firefox, whose pre-1.3.0 builds wrote the pair from every store page and whose reaper lives in the worker it does not have. The rest is event-driven: on chrome.runtime.onInstalled it picks the default ilap_surface_mode — a FRESH install persists 'widget' (+ arms the ilap_intro_glow chevron beacon); an UPDATE from the old popup-only build (key absent) is kept on 'popup' (+ arms the one-shot ilap_update_glow popup highlight). onStartup re-asserts 'widget' when the key is absent (a LOST onInstalled write would otherwise get mis-migrated to 'popup' by a later update) — delayed + yielding to a same-lifetime install/update event so it can't outrace the legacy popup migration

│   │   ├── steam-palette.js     # window.ILAP.SteamPalette: Steam's review-score palette, the ONE table both classifiers read (Classic Discovery Queue rows on the app page, Discovery Queue cards in the modal). Each band is a SET of shades, current first, the ones Steam painted before behind it — classification fails safe, so an older entry can only restore recognition after a rollback or a partial rollout, never invent one. It was two private copies until one drifted: Steam repainted Mixed in the modal, DQ kept comparing to the old shade, and Keep High Score silently ignored nothing for a whole release. isBad(colour) is what both classifiers call; current(band) is what the live guards assert against (the canary deliberately accepts ONLY current)

'done' (that account only, SteamID from the token's JWT) and 'none' (a minute) are cached for all tabs in ilap_sale_reward; 'pending'/'unknown' are never reused; checks in flight in one tab share one request; a DQ Start asks fresh over a cached 'none'

Both manifests match `https://store.steampowered.com/*` and exclude `https://store.steampowered.com/marketingmessages/*`. The Steam client opens that path as its special-offers window, which contains only promo posters, and the widget used to show up there.
