# Directory Structure & Script Load Order

## Directory Structure

```

│   ├── chromium/manifest.json   # MV3 manifest for Chrome/Edge
│   └── firefox/manifest.json    # MV3 manifest for Firefox
├── src/

Pure helpers only)
│   ├── presets.js               # window.ILAP.loadPresets (data/presets.json, read once per context), aiGames (the AI games of the lists less the kept kinds, the one rule the lists' +, the browsing level and the Classic DQ share) and aiKinds (the AI use the lists know a game for, translation or in game, which the AI flag names). Content script and popup
│   ├── settings-schema.js       # window.ILAP.Settings: the user settings' storage KEYS, DEFAULTS (the three gesture bindings, the Queue Helper mode), Q_MODES, GESTURES (the three right-button gesture values: what the MI detector checks before cancelling a menu that opens at press), BINDINGS (the six gesture-select values in menu order), OFF, UNIGNORE_KEYS, isOn (absent = on), normalizeShortcut (the legacy ignore-binding values) and normalizeUnignore (null for a value no build wrote). Pure; loaded right after escape.js in content_scripts and popup.html, and in the SW's importScripts — no module spells a settings key or default of its own, and none hand-rolls `!== false` either: a stored switch becomes a real boolean at the reader that fetches it (`ConfigReader._updateInternal`, `master-switch.js`, the popup's `_applyValues`). Also the AI tab's level: AI_LEVEL, AI_LEVELS (Off 0 to Max 4, Max never stored), AI_LEVEL_KEEP (the keep boxes each stored level sets), normalizeAiLevel, AI_SHOT, AI_SHOT_ANIM (the shot's animation, on unless false), SHOTS (the shot styles in menu order) and normalizeShot
│   ├── stats.js                 # window.ILAP.StatsLogic: the Last-Ignored record's shape — the three key names (ilap_ignored_count / _history / _last_ignored_name), the 20-entry history cap, and increment/decrement/pushHistory/nextState, plus countState and uncountState: the count-only halves, ±1, for an ignore that must be COUNTED but not SHOWN (a drained curator ignore — no name to display, and a job-sized batch would flush the history) and for a confirmed rollback, which takes its ignore back out of the total and equally leaves the history alone (a rolled-back entry still happened; what is UNDOABLE is ignore-log.js's question, not this one). The decrement is floored at 0: a rollback of a game ignored before install has no increment of its own to take back. ONE definition for the TWO worlds that WRITE it: utils.js StatsManager (content script) and background.js's shims (the SW recording a drained MI job via saveStats, a drained curator one via bumpCount, a drained undo via dropCount). Both worlds run all three writers on ONE serialized chain — they read-modify-write the same counter, so a second chain would lose a step where they overlap. Pure; only the chrome.storage read-modify-write around it stays per-world. popup.html loads it too, for the key names and the SOURCE labels only (it writes nothing). Also TOTAL_KEY (ilap_ignored_total, Steam's own ignore-list size as last read, with the counter as it stood then), totalState (that snapshot's write, on the same per-world chain as the counter writers: recordTotal in each world) and displayTotal (the popup's hover tip on the count: Steam's size plus what the counter moved since the read, null before any read — the counter is never a stand-in for it). Also SOURCE, every Last-Ignored history label (EQ and DQ, which their composition roots pass — the automators themselves save (name, appid) — and Manual Ignore's two), and miSourceLabel, the MI reason → label map both drain hosts use. Also looksAnonymous and contradictsTotal: a userdata read with no ignores, wishlist or library while the snapshot (within 7 days) says the account has ignores counts as no read, in both worlds

ONE definition for the TWO worlds that talk to Steam: loaded after escape.js in content_scripts and second in the SW's importScripts; popup.html never fetches Steam, so the storage-plumbing duplication rule (store.js) does not apply here. The ignore/unignore POST is NOT here — it stays per-world on purpose (see the file's own header). fetchIgnoredAppsStrict's map has `wishlist` and `owned` (rgWishlist / rgOwnedApps) as Sets, each null when the answer has no such list

The Classic DQ reads a game newer than the built-in lists with them. Also fromPage (the AI Generated Content Disclosure block on a store page, told from the Mature Content one of the same id by Steam's heading in every store language) and counts (whether a game counts as AI under the AI tab's boxes: a listed game by the lists' verdicts, any other by its disclosure and the word rules), shared by the Classic DQ's AiVerdict and the game page's AI note
│   ├── toast.js                 # window.ILAP.showToast(html, duration): the shared bottom-right push card (.ilap-toast + its own <style>), used by the curator button and Manual Ignore's queue-full warning and one-time menu-at-press hint. EQ/DQ keep their own toasts — those are interactive surfaces, not one-shot cards
│   ├── utils.js                 # Content-script infrastructure (loaded after escape.js + steam-net.js; re-exports the SteamNet reads as window.ILAP.fetchWithTimeout / .fetchIgnoredAppsStrict / .classifyRefusal / SteamAuth.probeLogin): the cookie session id, the ignore/unignore POST (one local post(fields) for both), readUserdata (the one reader behind fetchIgnoredApps, fetchWishlist and the facade's strict read, with StatsLogic's all-empty check), the lenient fetchIgnoredApps policy wrapper, the DOM login header (SteamAuth: resolveLogin for the UI locks, and hasLiveSession — the ONE ignore-side gate the rate governor and the Manual-Ignore gestures both ask, header trusted only when signed-IN, else the cached probe, tri-state so 'signed out' stays tellable from 'couldn't ask') and StatsManager
│   ├── creators.js              # window.ILAP.Creators: Steam's creator ignore as this extension knows it. The mirror ilap_creators (pure asMirror/noted/synced/unnamed/effective, serialized read/note, syncFromAccount after a userdata read), the ilap_creator_failed pulse, and the store tab's reads: a creator's name (og:title of /curator/<id>/?l=english), a creator page's clan id (its own IgnoreCurator( call), a game's creators (GetItems include_basic_info). Loaded in content_scripts after gate.js and in popup.html
│   ├── ignored-total.js         # Keeps ilap_ignored_total fresh while nothing drains (a drain pass records it for free from its own userdata read): on a store page load with the master switch on, when the snapshot and the last attempt (ilap_ignored_total_poll, any tab) are both older than 15 min, claims the attempt, then reads userdata only on a live session (SteamAuth.hasLiveSession) — a signed-out read is an empty list and must never become 0, so an EMPTY read is kept only after a fresh probeLogin (the header can show signed-in on a session that has died since). Within 15 s of the last gate slot (IgnoreGate.lastSlotAt — userdata lags a fresh POST) it reads nothing and claims nothing. Not per account: a switch shows the old number for up to one TTL. Both platforms, after gate.js
│   ├── game-name.js             # window.ILAP.getGameName (sync) / resolveGameName (async): a game's display name from the DOM around one of its links — five strategies behind NameExtractionStrategyProvider.find (null when all miss), the "AppID <id>" placeholder applied at the facade, and SteamNet.fetchAppName as the async last resort. After utils.js and steam-net.js
│   ├── sw-handoff.js            # The page's half of the SW drain: caches the cookie sessionid into ilap_sw_sid (the worker cannot read document.cookie) and clears ilap_sw_halt, writing only on change so a same-value write never wakes the worker. Runs on every store page, after utils.js and curator/store.js (whose SW_SID_KEY / SW_HALT_KEY it writes). CHROMIUM ONLY — the Firefox manifest leaves it out on purpose: that platform drains from the content script, so nothing there would read the cached sessionid and nothing would clear it either (the reaper lives in the worker)
│   ├── master-switch.js         # window.ILAP.MasterSwitch.watch({ onInit, onChange }): the global `ilap_master_enabled` read once, then followed live (absent = ON; the change listener attaches only after the first read lands). For content-script modules that need that key alone — Discovery Queue controller, curator button; EQ, Manual Ignore and the widget read it inside their wider settings snapshots
│   ├── gate.js                  # window.ILAP.IgnoreGate: aggregate ignore-POST rate governor (reserve() a slot before every ignore across drainer/EQ/DQ; ilap_ignore_gate fixed min-gap; master + dead-session stop, the latter via SteamAuth.hasLiveSession — NOT from the sessionid cookie, which anonymous visitors also have; stopVerdict is asked OUTSIDE the claim chain because it can cost a network round trip, and it reports 'offline' apart from 'no-session' because "could not ask" and "signed out" do not recover alike — only 'disabled' is a state the extension itself owns, which is the one the SW parks its retry alarm on) — closes audit #1/#2. While the user is active on a Steam page (ilap_user_active_at, last 30 s) a background reservation without { gesture: true } waits ACTIVE_GAP (3 s) instead; noteNativeIgnore(status) folds an ignore POST that Steam's own page sent into the same stream (slot moved up to now, a 429 escalates the penalty). quietUntil() says when background work may go again (the penalty's end, the foreground yield), which a drain host asks before opening a pass
│   ├── steam-activity.js        # The user's own activity on a Steam store page, told to IgnoreGate while the master switch is on (MasterSwitch.watch; off, it writes nothing): page load + trusted pointerdown/keydown outside the extension's own UI → noteUserActivity (throttled, 5 s); a PerformanceObserver on the page's resource timeline sees every ignore POST the PAGE sends (XHR or fetch, with or without the trailing slash, status via responseStatus — no extra permission, isolated world, verified live on Chromium and Firefox) → noteNativeIgnore; skips our own POSTs, which land in that timeline on Firefox, via ILAP.OwnIgnorePosts (utils.js). Content script only
│   ├── ignore-log.js            # window.ILAP.IgnoreLog: timestamped append log of every EXTENSION ignore {appid,name?,ts,source,curatorId?,undoneAt?} (cap 20000 FIFO; an MI change of reason is not logged — Undo only takes games off the list), chunked across ilap_ignore_log_index + ilap_ignore_log_c<seq> so a drain's append writes one small key; the undo feature's data source (Steam's rgIgnoredApps has no dates). │   ├── undo-service.js          # window.ILAP.UndoService: injectable staging for undo jobs — a STATIC appid snapshot from the log (count or time scope) pushed into the shared curator queue as {type:'undo', curatorId:'undo'} (one at a time, same 3-job cap); the drainer branches on the type to POST remove=1
│   ├── surface.js               # window.ILAP.Surface: ilap_surface_mode helper (widget|popup mode, Steam-client UA detect, Ctrl+Alt+Shift+I escape-hotkey + per-platform label + shift-click mouse twin) — pure, loaded in content scripts AND popup.html
│   ├── background.js            # Chromium MV3 service-worker ENTRY (Phase 3; NOT in the --test build, which swaps in the empty background-test.js). Shims window→self, importScripts's escape.js + settings-schema.js + stats.js + steam-net.js + migrate.js + gate.js + ignore-log.js + curator/lease.js + curator/store.js + curator/drainer.js, then hosts a CuratorQueueDrainer that drains the queue with NO Steam tab open — it joins the existing lease/handoff protocol as just another drainer. SW-specific parts: sessionid from the ilap_sw_sid cache (mirrored into memory for the gate's sync read), its own ignore POST (the one Steam call that stays per-world — the reads come from steam-net.js) and its own storage RMW for stats (the record's shape comes from stats.js), a gate wrapper that refuses waits >20 s (the SW would die mid-sleep; a chrome.alarms alarm resumes at the penalty's end instead) and the ilap_sw_halt circuit breaker (2 consecutive failed POSTs — stale sid / missing Steam_Language — halt BEFORE the drainer's MAX_FAILS skip burns an appid; any store-page visit re-arms). One retry alarm ('ilap_sw_drain', ≥60 s) re-armed while drainable work remains, cleared when the queue empties, when the route is halted, or on a master-off stop — the only stop whose cure is a storage write this worker hears. │   ├── migrate.js               # Profile migrations (on Chromium loaded into the SW via background.js importScripts; on Firefox the sole event-page script; NOT in the --test build).
```
