# Storage Keys Reference

| Key | Storage | Purpose |
|-----|---------|---------|
| `ilap_ignored_count` | local | Total games ignored |
| `ilap_ignored_history` | local | Last 20 ignored games |
| `ilap_last_ignored_name` | local | Most recent game |
| `ilap_shortcut_key` | local | Default ignore shortcut |
| `ilap_platform_key` | local | Alternative shortcut |
| `ilap_master_enabled` | local | Global on/off |
| `ilap_dq_active` | local | Cross-tab cap on concurrently-active Discovery-Queue automators (`window.ILAP.Discovery.Registry`): a heartbeated owner map `{ ownerId: expiresAt }`, TTL-reclaimed like the curator lease so a closed tab frees its slot. `DiscoveryQueueController` claims a slot on Start (refuses with a transient "max {n} running" button message when ≥`CAP`=2 other live owners fill it), renews every 3 s while running, releases on stop. A UX bound, not a safety one — the `ilap_ignore_gate` governor already caps the aggregate POST rate; this just stops silent stacking of DQ loops. Cross-tab residual: no CAS, so two tabs racing can briefly make 3 active (accepted). Also accepted: Chrome throttles a backgrounded tab's timers, so a hidden DQ tab's heartbeat can lapse and its slot expire while its automator keeps ignoring (background loops run, slower) — the cap can undercount, but the rate gate still bounds the aggregate POST rate |
| `ilap_ignore_gate` | local | Aggregate ignore-POST rate governor (`window.ILAP.IgnoreGate`): a single last-reserved-slot timestamp. Every ignore SOURCE — curator drainer, EQ automator, and the DQ icon click (which makes Steam's own page JS fire the ignore POST — confirmed, so DQ is NOT request-free) — calls `reserve()` before emitting an ignore; it advances this timestamp by ~500 ms + jitter (350 ms floor) via a per-context serialized RMW, so the aggregate rate across all tabs/sources of a profile stays ≤ ~2/s and stacked sources collapse into one paced stream. `reserve()` also STOPS (no slot) when `ilap_master_enabled=false` (closes audit #1: master vs drainer) or no `sessionid` cookie (closes audit #2: dead session must not burn work); both stop conditions are RE-CHECKED after the pacing wait (a master flip / logout mid-wait can't be followed by one more ignore — DQ additionally re-checks `isRunning`, the drainer re-reads the job status, so a Stop/Pause during the wait stops before the POST). A stored slot further than `MAX_AHEAD` (30 s + `PENALTY_MAX`, since a 429 penalty from `ilap_ignore_gate_penalty` can legitimately push the slot minutes ahead) in the future is clock skew (manual clock change, resumed VM) and is clamped to now, not waited out. Manual-ignore is intentionally NOT gated (human-paced, negligible). Cross-tab residual: no CAS, so two tabs can rarely share a slot — accepted, same class as the stats/queue RMW races |
| `ilap_ignore_gate_penalty` | local | Rate-limit backoff for the ignore governor (`{ until, level }`), written by `IgnoreGate.reportRateLimited()` when the ignore endpoint answers **429** (`SteamAPI.ignore` now resolves `{ ok, rateLimited, retryAfterMs, status }` — `status` is the raw HTTP code (0 when the request never completed), read only by the curator drainer's 400-classifier so a timeout/5xx can't be mistaken for a region-lock refusal; the drainer ends its pass without burning `fails` on the appid, EQ reports and stalls — DQ can't see HTTP status, its POST is fired by Steam's page JS). `reserve()` folds an active `until` into the next slot, so every source in every tab goes quiet together; a source already HOLDING a reserved slot still fires it (accepted residual: ≤1 in-flight ignore per source after a 429). Escalation: 5 s doubling to a 5 min cap (`PENALTY_BASE`/`PENALTY_MAX`), honouring a numeric `Retry-After` up to the same cap; consecutive 429s escalate while each lands within `PENALTY_DECAY` (60 s) of the previous penalty's end, a quiet spell resets to level 1. An `until` further than `PENALTY_MAX` in the future is corruption/skew and is ignored (same rationale as the gate's `MAX_AHEAD`, which grew to 30 s + `PENALTY_MAX` so a legitimate penalty-pushed slot isn't clamped as skew). Cross-tab residual: no CAS, two tabs reporting the same 429 can double-escalate — accepted, over-backing-off is the safe direction |
| `ilap_q_master` | local | Queue automator enable |
| `ilap_q_next` | local | Auto-advance after ignore |
| `ilap_q_mode` | local | `"bad"` or `"all"` |
| `ilap_dq_open` | local | SETTINGS panel: "Your Discovery Queue" subcategory expanded (default collapsed). Restored on each settings render, persisted on `<details>` toggle. Mutually exclusive with `ilap_mi_open` — opening one collapses the other |
| `ilap_mi_open` | local | SETTINGS panel: "Manual Ignore" subcategory expanded (default collapsed); mutually exclusive with `ilap_dq_open` |
| `ilap_session_map_v2` | session | appid → reason map |
| `ilap_queue_active` | session | Explore queue ACTIVE intent |
| `ilap_queue_ff` | session | Explore queue fast-forward intent |
| `ilap_queue_nav_token` | session | 15 s navigation authorization token |
| `ilap_curator_queue` | local | Ignore-task jobs (≤3, +1 for MI), user-owned fields only (all writes via `Store.mutateQueue`). Three job types: curator jobs (appids + filter + status: enumerating/pending/paused); at most ONE undo job (`type:'undo'`, `curatorId:'undo'` — the pseudo-id keys its drain lease — plus a STATIC `appids` snapshot from `ilap_ignore_log` and `snapshotTs`, the "last user intent wins" boundary: the drainer skips an appid re-ignored after it); and at most ONE Manual-Ignore job (`type:'mi'`, `curatorId:'mi'`, id `job_mi`). The MI job is AUTO-FILLED: a swipe no longer fires an ungated instant POST — it optimistically badges the game and `Store.enqueueMi` appends `{appid}` to this job with a per-appid `meta[appid]={name,reason}` (the drainer POSTs the right reason and stamps Last Ignored at drain time); `appids` stays a plain string array for the generic paths. `MI_MAX=200` caps it (a swipe past = silent no-op); it is the ONE type allowed to exceed the 3-job cap (exclusive 4th slot, top drainer priority via MI-first `_pickJob`), and auto-deletes when drained empty. Drain-time only (§7): `saveStats` + `log.append(source:'mi')` are gated strictly to MI so curator/undo never touch Last Ignored. Undo jobs get the same lease/handoff, cursor key, Pause/Remove and gate pacing; the drainer branches on the type to POST `remove=1` with INVERSE userdata dedupe (a skip also marks the log entries `undoneAt`). Because the inverse dedupe reads "not in the set" as "already rolled back", an undo pass STOPS (job intact, retried later) on a failed strict userdata read, and an EMPTY set is only trusted after a live `SteamAuth.probeLogin()` — a logged-out userdata read returns the same empty defaults and would otherwise skip-burn the job with zero requests. Per-appid the same trust is time-gated: `rgIgnoredApps` lags a fresh ignore POST by seconds, so an appid absent from the set but whose newest live `ilap_ignore_log` ts is within `UNDO_FRESH_MS` (~15 s) is un-ignored anyway (`remove=1` is idempotent) instead of skip-marked, so a just-ignored game staged into an undo isn't stranded in the ignore list with its log entry burned out of the undoable pool |
| `ilap_ignore_log` | local | Undo data source (`window.ILAP.IgnoreLog`): append log of every ignore the EXTENSION performed — `{ appid, name?, ts, source: mi\|eq\|dq\|curator, curatorId?, undoneAt?, skipped? }`, FIFO-capped at 5000. Entries with `skipped:'unavailable'` record a region-locked appid a curator drain stepped over (a refusal, NOT an ignore) — inert for every undo selector, kept as the durable "the job wasn't a full done" trace. Written beside `saveStats` by the MI/EQ/DQ stats adapters (they pass the appid through) and by the curator drainer per confirmed ignore (appid-only — enumeration has no names). Steam's own `rgIgnoredApps` carries no dates, so count- AND time-scoped undo both operate on OUR `ts`. The undo drainer marks rolled-back entries `undoneAt` (kept, not deleted) so a later undo can't re-undo them and the curator droplist can warn on a re-stage within 48 h (`lastUndoneForCurator`); inverse-dedupe skips (appid already un-ignored elsewhere) are marked too, so stale entries can't inflate the undoable count forever. Undo deliberately does NOT touch `ilap_ignored_count`/history (curator drains never incremented them — a decrement would corrupt). Serialized-RMW writes; cross-tab no-CAS residual accepted (at worst one log entry lost, cosmetic). This is a drain-progress key for the popup render path (written 1–3×/s mid-drain → light re-render only) |
| `ilap_curator_cache` | local | Per-curator enumerated apps cache (TTL 7 d, LRU ≤10) |
| `ilap_curator_cursor_<jobId>` | local | Drainer-owned per-job progress cursor (single writer = lease holder; removed with the job). `Store.setCursor` refuses the write when the job is no longer in the queue, so a remove racing a resolve/drain iteration can't recreate (leak) the key after its only cleanup path ran |
| `ilap_curator_skipped_<jobId>` | local | Drainer-owned per-job count of appids skipped as permanently refused (400 classified as region-locked via an appdetails probe: no store object in the account's region). Same single-writer/partitioning/cleanup discipline as the cursor key; surfaced in the queue applet's job row |
| `ilap_curator_lock_<id>` | local | Per-job drain lease `{ owner, expiresAt }` (single-drainer handoff); a live lease is also the UI's derived "running" signal |
| `ilap_curator_pulse` | local | Timestamp written when a job finishes; widget watches it to blink once (finished jobs are removed, not kept) |
| `ilap_unignored` | local | `{ appid, ts }` pulse written by the undo drainer after EACH confirmed `remove=1` (`Store.signalUnignored`). Every Manual-Ignore content script watches it via `onChanged` and clears that game's on-page IGNORED badge (`BadgeRenderer.unrender` + drop from the per-tab `sessionMap`) — only for appids THIS tab badged. Per-appid (not batched at job end) so the badge rolls back as each game does; fixes the pre-existing "un-ignore leaves the badge lying on the page" gap |
| `ilap_sw_sid` | local | Cached `sessionid` for the SW drainer (`src/background.js`, Chromium only): under `permissions: ["storage"]` the service worker cannot read `document.cookie`, so the curator-drainer boot block caches the cookie here on every store page. Change-only write (a same-value write would wake the SW via `onChanged` for nothing); written at page boot rather than enqueue time so a re-login refreshes it. The SW mirrors it into memory (the gate's `getSessionID` reads it synchronously); no value → the gate's `no-session` stop applies. Firefox: written but unconsumed (no SW drain there — unverified fetch behavior) |
| `ilap_sw_halt` | local | SW-drain circuit breaker: set true by the SW after 2 CONSECUTIVE failed ignore POSTs (429s excluded — that's the gate penalty's job; 400s classified as region-locked appids excluded too — they're per-appid, not systemic, and are skipped/counted instead, so the "open a store page" hint stays truthful). A stale cached sid (re-login with no store tab open) or a missing `Steam_Language` cookie fails EVERY POST, and the drainer's `MAX_FAILS` (3) skip would then burn appids one by one; the halt engages at 2 — before the first skip — and the SW's gate wrapper refuses every slot while it's set. Cleared by the drainer boot on any store-page visit, which also re-caches the sid (one user action fixes both causes; the popup queue applet shows a `queue_sw_halt` hint pointing there). Tab drainers ignore the flag — their cookie jar is live |
| `ilap_widget_expanded_ts` | local | Widget launcher state: 0/absent = collapsed to the chevron tab (default); >0 = expanded, value = last-activity timestamp (bumped on widget clicks, throttled 5 s). Any tab's 60 s idle timer stashes the launcher; an open panel re-bumps instead |
| `ilap_widget_pinned` | local | Widget pin badge (launcher corner, shown on hover): true = launcher pinned out — idle timers re-bump instead of stashing, stale-timestamp mounts stay expanded — until the user unpresses the pin. Gated by `ilap_master_enabled`: while the extension is disabled the pin goes inert (`.ilap-pin.disabled` — greyed + `pointer-events:none` + a click-handler guard), reveals on a launcher hold so its state stays visible but can't be toggled; the rest of the widget (chevron, launcher, panel, master toggle) is NOT master-gated so the extension can always be re-enabled from the panel |
| `ilap_surface_mode` | local | Which surface hosts the popup UI: `'widget'` (default) = on-page shadow-DOM widget; `'popup'` = the `chrome.action` toolbar popup (`ui/popup.html`). In popup mode the on-page widget parks to a ghost-chevron beacon. The mode ONLY decides where the UI lives — since the SW drain (`src/background.js`) the queue progresses with no Steam tab, so the old "popup mode ⇒ empty curator queue" invariant and the popup-mode staging locks (curator button, undo droplist) are REMOVED: switching is free in both directions with a busy queue, and staging works from either surface (the deleted `curator_locked_popup`/`surface_popup_blocked` i18n keys died with the locks). The widget-mode toolbar stub shows an aggregate queue progress line + the `ilap_sw_halt` hint instead of the full applet. The Steam desktop client (CEF, no toolbar) forces widget regardless of the stored value via `Surface.resolve(stored, navigator.userAgent)` — the key is never overwritten. Escape hatch: **Ctrl+Alt+Shift+I** on any store page writes `'widget'`. **Default set at install/update by `src/migrate.js` (loaded into the background context — on Chromium via `importScripts` in `src/background.js`, on Firefox as the sole background script; the whole background is swapped out in `--test` builds):** a fresh install persists `'widget'`; an update from the old popup-only build (key absent) is migrated to `'popup'` so existing users keep the toolbar popup they know. **Sign-in push:** when the surface flips popup→widget while logged out, the widget shows a 10 s on-page `.ilap-push` — a bottom-right toast styled like the curator's `.ilap-curator-toast` (icon + text, blue left-accent, slide-up), with the same copy as the launcher's login tooltip (`widget_login_required`) — so the user knows the on-page surface needs a Steam sign-in. The launcher's own login tooltip (`.ilap-login-tip`) is offset left of the full-width launcher (`right: ICON+8`) so it doesn't sit over the icon |
| `ilap_intro_glow` | local | New-install chevron beacon, armed by `src/migrate.js` on a FRESH install only (alongside `ilap_surface_mode:'widget'`): while true, the collapsed chevron keeps the steady blue rim (`.restored`) and radiates the gold halo (`.gold`) in 10 s bursts once a minute (`INTRO_BURST_MS`/`INTRO_CYCLE_MS` — a non-stop pulse would nag) — a first-time user has never seen the on-page surface and the slim tab is easy to miss. Retired (set false, mirrored to every tab via onChanged) by the first chevron click anywhere; never re-armed. Suppressed while the chevron is the popup-mode ghost beacon (`.restored` would force full opacity on a deliberately faint ghost) |
| `ilap_update_glow` | local | One-shot post-update popup highlight, armed by `src/migrate.js` ONLY on the same absent-key update that migrates a pre-surface-switch profile to `'popup'` (so later updates can never re-arm it): at the next `popup.html` bootstrap a 5 s light gold inset wash (`#popup-root.update-glow`, popup.css) plays over the full popup UI — "yes, this is still your extension". The flag is consumed (set false) at that FIRST bootstrap whatever it rendered: a reopen even within the 5 s window never replays the glow, and a stub render (the user reached widget mode before ever opening the popup — they've plainly found the extension) retires a stale flag silently, so a later widget→popup switch doesn't glow either |
