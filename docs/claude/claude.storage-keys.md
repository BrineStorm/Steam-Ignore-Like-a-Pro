# Storage Keys Reference

| Key | Storage | Purpose |
|-----|---------|---------|
| `ilap_ignored_count` | local | Total games ignored |
| `ilap_ignored_history` | local | Last 20 ignored games |
| `ilap_last_ignored_name` | local | Most recent game |
| `ilap_shortcut_key` | local | Default ignore shortcut |
| `ilap_platform_key` | local | Alternative shortcut |
| `ilap_master_enabled` | local | Global on/off |
| `ilap_dq_active` | local | Cross-tab cap on concurrently-active Discovery-Queue automators (`window.ILAP.Discovery.Registry`): a heartbeated owner map `{ ownerId: expiresAt }`, TTL-reclaimed like the curator lease so a closed tab frees its slot. `DiscoveryQueueController` claims a slot on Start (refuses with a transient "max {n} running" button message when ≥`CAP`=2 other live owners fill it), renews every 3 s while running, releases on stop. A UX bound, not a safety one — the `ilap_ignore_gate` governor already caps the aggregate POST rate; this just stops silent stacking of DQ loops. Cross-tab residual: no CAS, so two tabs racing can briefly make 3 active (accepted). Also accepted: Chrome throttles a backgrounded tab's timers, so a hidden DQ tab's heartbeat can lapse and its slot expire while its automator keeps ignoring (background loops run, slower) — the cap can undercount, but the rate gate still bounds the aggregate POST rate |
| `ilap_ignore_gate` | local | Aggregate ignore-POST rate governor (`window.ILAP.IgnoreGate`): a single last-reserved-slot timestamp. Every ignore SOURCE — curator drainer, EQ automator, and the DQ icon click (which makes Steam's own page JS fire the ignore POST — confirmed, so DQ is NOT request-free) — calls `reserve()` before emitting an ignore; it advances this timestamp by ~500 ms + jitter (350 ms floor) via a per-context serialized RMW, so the aggregate rate across all tabs/sources of a profile stays ≤ ~2/s and stacked sources collapse into one paced stream. `reserve()` also STOPS (no slot) when `ilap_master_enabled=false` (closes audit #1: master vs drainer) or no `sessionid` cookie (closes audit #2: dead session must not burn work); both stop conditions are RE-CHECKED after the pacing wait (a master flip / logout mid-wait can't be followed by one more ignore — DQ additionally re-checks `isRunning`, the drainer re-reads the job status, so a Stop/Pause during the wait stops before the POST). A stored slot further than `MAX_AHEAD` (30 s + `PENALTY_MAX`, since a 429 penalty from `ilap_ignore_gate_penalty` can legitimately push the slot minutes ahead) in the future is clock skew (manual clock change, resumed VM) and is clamped to now, not waited out. Manual-ignore is intentionally NOT gated (human-paced, negligible). Cross-tab residual: no CAS, so two tabs can rarely share a slot — accepted, same class as the stats/queue RMW races |
| `ilap_ignore_gate_penalty` | local | Rate-limit backoff for the ignore governor (`{ until, level }`), written by `IgnoreGate.reportRateLimited()` when the ignore endpoint answers **429** (`SteamAPI.ignore` now resolves `{ ok, rateLimited, retryAfterMs }`; the drainer ends its pass without burning `fails` on the appid, EQ reports and stalls — DQ can't see HTTP status, its POST is fired by Steam's page JS). `reserve()` folds an active `until` into the next slot, so every source in every tab goes quiet together; a source already HOLDING a reserved slot still fires it (accepted residual: ≤1 in-flight ignore per source after a 429). Escalation: 5 s doubling to a 5 min cap (`PENALTY_BASE`/`PENALTY_MAX`), honouring a numeric `Retry-After` up to the same cap; consecutive 429s escalate while each lands within `PENALTY_DECAY` (60 s) of the previous penalty's end, a quiet spell resets to level 1. An `until` further than `PENALTY_MAX` in the future is corruption/skew and is ignored (same rationale as the gate's `MAX_AHEAD`, which grew to 30 s + `PENALTY_MAX` so a legitimate penalty-pushed slot isn't clamped as skew). Cross-tab residual: no CAS, two tabs reporting the same 429 can double-escalate — accepted, over-backing-off is the safe direction |
| `ilap_q_master` | local | Queue automator enable |
| `ilap_q_next` | local | Auto-advance after ignore |
| `ilap_q_mode` | local | `"bad"` or `"all"` |
| `ilap_dq_open` | local | SETTINGS panel: "Your Discovery Queue" subcategory expanded (default collapsed). Restored on each settings render, persisted on `<details>` toggle. Mutually exclusive with `ilap_mi_open` — opening one collapses the other |
| `ilap_mi_open` | local | SETTINGS panel: "Manual Ignore" subcategory expanded (default collapsed); mutually exclusive with `ilap_dq_open` |
| `ilap_session_map_v2` | session | appid → reason map |
| `ilap_queue_active` | session | Explore queue ACTIVE intent |
| `ilap_queue_ff` | session | Explore queue fast-forward intent |
| `ilap_queue_nav_token` | session | 15 s navigation authorization token |
| `ilap_curator_queue` | local | Curator ignore jobs (≤3), user-owned fields only (appids + filter + status: enumerating/pending/paused; all writes via `Store.mutateQueue`) |
| `ilap_curator_cache` | local | Per-curator enumerated apps cache (TTL 7 d, LRU ≤10) |
| `ilap_curator_cursor_<jobId>` | local | Drainer-owned per-job progress cursor (single writer = lease holder; removed with the job). `Store.setCursor` refuses the write when the job is no longer in the queue, so a remove racing a resolve/drain iteration can't recreate (leak) the key after its only cleanup path ran |
| `ilap_curator_lock_<id>` | local | Per-job drain lease `{ owner, expiresAt }` (single-drainer handoff); a live lease is also the UI's derived "running" signal |
| `ilap_curator_pulse` | local | Timestamp written when a job finishes; widget watches it to blink once (finished jobs are removed, not kept) |
| `ilap_widget_expanded_ts` | local | Widget launcher state: 0/absent = collapsed to the chevron tab (default); >0 = expanded, value = last-activity timestamp (bumped on widget clicks, throttled 5 s). Any tab's 60 s idle timer stashes the launcher; an open panel re-bumps instead |
| `ilap_widget_pinned` | local | Widget pin badge (launcher corner, shown on hover): true = launcher pinned out — idle timers re-bump instead of stashing, stale-timestamp mounts stay expanded — until the user unpresses the pin. Gated by `ilap_master_enabled`: while the extension is disabled the pin goes inert (`.ilap-pin.disabled` — greyed + `pointer-events:none` + a click-handler guard), reveals on a launcher hold so its state stays visible but can't be toggled; the rest of the widget (chevron, launcher, panel, master toggle) is NOT master-gated so the extension can always be re-enabled from the panel |
| `ilap_surface_mode` | local | Which surface hosts the popup UI: `'widget'` (default) = on-page shadow-DOM widget; `'popup'` = the `chrome.action` toolbar popup (`ui/popup.html`, restored — no SW). In popup mode the on-page widget parks to a ghost-chevron beacon and the curator "Add to ignore queue" button stays in place but LOCKED (greyed + an inline `.ilap-locked-tip` hover tooltip with `curator_locked_popup`, aria-linked for AT; the dropdown is forced shut and a pick is refused at click time, so a menu left open across a live surface flip in this or another window can't sneak a stage in). Invariant: popup mode is only reachable while `ilap_curator_queue` is empty (settings toggle + stub button both re-check `Store.getQueue()`). The Steam desktop client (CEF, no toolbar) forces widget regardless of the stored value via `Surface.resolve(stored, navigator.userAgent)` — the key is never overwritten. Escape hatch: **Ctrl+Alt+Shift+I** on any store page writes `'widget'`. **Default set at install/update by `src/migrate.js` (the sole background context, absent from `--test` builds):** a fresh install persists `'widget'`; an update from the old popup-only build (key absent) is migrated to `'popup'` so existing users keep the toolbar popup they know. **Sign-in push:** when the surface flips popup→widget while logged out, the widget shows a 10 s on-page `.ilap-push` — a bottom-right toast styled like the curator's `.ilap-curator-toast` (icon + text, blue left-accent, slide-up), with the same copy as the launcher's login tooltip (`widget_login_required`) — so the user knows the on-page surface needs a Steam sign-in. The launcher's own login tooltip (`.ilap-login-tip`) is offset left of the full-width launcher (`right: ICON+8`) so it doesn't sit over the icon |
| `ilap_intro_glow` | local | New-install chevron beacon, armed by `src/migrate.js` on a FRESH install only (alongside `ilap_surface_mode:'widget'`): while true, the collapsed chevron keeps the steady blue rim (`.restored`) and radiates the gold halo (`.gold`) in 10 s bursts once a minute (`INTRO_BURST_MS`/`INTRO_CYCLE_MS` — a non-stop pulse would nag) — a first-time user has never seen the on-page surface and the slim tab is easy to miss. Retired (set false, mirrored to every tab via onChanged) by the first chevron click anywhere; never re-armed. Suppressed while the chevron is the popup-mode ghost beacon (`.restored` would force full opacity on a deliberately faint ghost) |
| `ilap_update_glow` | local | One-shot post-update popup highlight, armed by `src/migrate.js` ONLY on the same absent-key update that migrates a pre-surface-switch profile to `'popup'` (so later updates can never re-arm it): at the next `popup.html` bootstrap a 5 s light gold inset wash (`#popup-root.update-glow`, popup.css) plays over the full popup UI — "yes, this is still your extension". The flag is consumed (set false) at that FIRST bootstrap whatever it rendered: a reopen even within the 5 s window never replays the glow, and a stub render (the user reached widget mode before ever opening the popup — they've plainly found the extension) retires a stale flag silently, so a later widget→popup switch doesn't glow either |
